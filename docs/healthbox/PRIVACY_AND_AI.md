# Privacy and AI limitations

HealthBox stores sensitive health records. Configure accounts, reciprocal
visibility and administrator access deliberately. A hidden URL is not access
control. The administrator can access server data; this must be disclosed.

Original reports are retained separately from derived facts. OCR is limited to
supported paths and metrics and can be wrong. Review before formal submission.
Unknown fields remain unresolved rather than being invented. Complex layouts,
handwriting and broad hospital-template coverage are not validated.

The local AI adapter is disabled by default. It uses a bounded formal-record
selection, explicit citations, read-only contracts, request budgets and separate
answer history. It cannot alter originals or formal observations. The mobile
browser does not receive server/database write tools. The current test provider
is not a language model. Arbitrary in-app medical questions, cloud providers,
individual screening schedules and disease probabilities are not implemented.

No negative test or normal number proves a person is disease-free. Education
topics do not constitute individualized screening or treatment advice. This
software is not a diagnostic system or emergency monitoring service.

Threats requiring deployment review include account compromise, cross-subject
access, leaked downloads/exports, malicious files, denial of service, operator
access, backup theft, stale guidance and model hallucinations. The current
candidate has outstanding validation and licensing gates; see the release
checklist before sharing it publicly.
